# s15-ms Design: EMG Metric Audit + Conditional Replication

**Date:** 2026-04-23
**Supersedes / succeeds:** s13 (coupled fs ladder) and s14 (per-muscle ratio grid)
**Thinking doc:** `docs/superpowers/specs/2026-04-23-s15-ms-thinking.md`

## Problem

Across s10–s14 (358 runs) no configuration clears all four gates simultaneously:

- `eval/episode_reward ≥ 400`
- `eval/emg_biceps_corr ≥ 0.4` AND `eval/emg_biceps_mae ≤ 0.15`
- `eval/emg_triceps_corr ≥ 0.4` AND `eval/emg_triceps_mae ≤ 0.15`

Best single run: **s13-armM-anchorA-fs1p1-s2** (R=411, bcorr=0.70, tcorr=0.58, bmae=0.12, tmae=0.13). Only 5 "goldilocks" cells exist across 358 runs, and all are s11/s13. s14's per-muscle ratios showed triceps-corr gains paid for entirely by 3–5× biceps MAE blow-up (0 runs at R≥400 ∧ bmae≤0.15 vs s13's 24).

## Root-cause hypothesis

Current metric pipeline contains two confounds that prevent us from knowing whether any existing checkpoint already solves the problem:

1. **Amplitude clipping.** Reference EMG is normalized as `arr / np.percentile(arr, 98)` in `train_mouse_janelia_sigmoid_moving_shoulder.py:143`. The top 2% of samples exceed 1.0. MuJoCo `data.act` is hard-bounded at 1.0 (Hill model, `train_mouse_janelia_sigmoid_moving_shoulder.py:2017`). The policy cannot match peak burst amplitude, and to match peak *duration* it plateaus at 1.0 — which distorts peak timing. Apparent phase shift follows.
2. **Missing phase-aware metrics.** Neither `trial_corr` (spec'd in s13 P1) nor `lagged_corr`/`phase_lag` (spec'd in s14 P1) was ever implemented. Every s10–s14 `corr` number is mean-trace-only and conflates shape error with timing error.

## Strategy: three-stage, gate-on-measurement

### Stage 1 — Infra fixes (code only, no GPU)

Changes to `train_mouse_janelia_sigmoid_moving_shoulder.py` and `scripts/emg_comparison.py`. Both files must compute metrics identically.

**1.1 EMG renormalization (the amplitude fix)**
- New CLI flag: `--emg-norm-percentile FLOAT` (default **100.0**).
- Change `arr / np.percentile(arr, 98)` → `arr / np.percentile(arr, args.emg_norm_percentile)`.
- At p100, the reference max is exactly 1.0 — no clipping, no amplitude mismatch versus sim.
- Fixed at dataset-wide per-muscle scope for now (same as current). A `--emg-norm-mode per_trial` flag is deferred to Stage 3 (see branch 4).

**1.2 Per-trial Pearson correlation**
- Extend `compute_emg_metrics` (line 159) to compute per-trial r across paired bio/sim trials:
  ```python
  n_pairs = min(sim_muscle.shape[0], bio_traces.shape[0])
  trial_corrs = []
  for i in range(n_pairs):
      s = sim_muscle[i]; b = bio_traces[i]
      if s.std() > 0 and b.std() > 0:
          trial_corrs.append(np.corrcoef(s, b)[0, 1])
  result["trial_corr_mean"] = float(np.nanmean(trial_corrs)) if trial_corrs else np.nan
  result["trial_corr_median"] = float(np.nanmedian(trial_corrs)) if trial_corrs else np.nan
  ```
- Log `eval/emg_{muscle}_trial_corr_mean` and `eval/emg_{muscle}_trial_corr_median`.

**1.3 Lagged (phase-shift) correlation — expanded metric set**

Compute the full cross-correlation curve over ±20 steps (±50 ms at ctrl-dt=2.5 ms) and extract multiple features. These are logged during every eval cycle of training (`eval_and_log` in `train_mouse_janelia_sigmoid_moving_shoulder.py:1902`) so we can watch lag evolve across the run in wandb, not just at final eval.

```python
LAG_RANGE_STEPS = 20  # ±20 steps × 2.5 ms/step = ±50 ms window

def compute_lag_metrics(sim_mean, emg_mean):
    lags = np.arange(-LAG_RANGE_STEPS, LAG_RANGE_STEPS + 1)
    corrs = []
    for lag in lags:
        if lag < 0: s, b = sim_mean[-lag:], emg_mean[:len(sim_mean)+lag]
        elif lag > 0: s, b = sim_mean[:-lag], emg_mean[lag:]
        else: s, b = sim_mean, emg_mean
        if s.std() > 0 and b.std() > 0 and len(s) > 2:
            corrs.append(np.corrcoef(s, b)[0, 1])
        else:
            corrs.append(np.nan)
    corrs = np.asarray(corrs)
    argmax = int(np.nanargmax(corrs))
    best_r = float(corrs[argmax])
    best_lag = int(lags[argmax])
    # FWHM of cross-correlation curve around peak
    half_max = best_r / 2.0
    above = corrs >= half_max
    fwhm_steps = int(np.sum(above))
    return {
        "lagged_corr_max": best_r,
        "phase_lag_steps": best_lag,
        "phase_lag_ms": best_lag * 2.5,
        "lagged_corr_at_0": float(corrs[LAG_RANGE_STEPS]),           # = mean_corr
        "lagged_corr_at_neg5": float(corrs[LAG_RANGE_STEPS - 5]),
        "lagged_corr_at_pos5": float(corrs[LAG_RANGE_STEPS + 5]),
        "lagged_corr_fwhm_steps": fwhm_steps,
    }
```

Also compute a **per-trial** lag analysis (each trial gets its own best-lag corr, then aggregate):

```python
def compute_per_trial_lag_metrics(sim_muscle, bio_traces):
    per_trial = []
    n_pairs = min(sim_muscle.shape[0], bio_traces.shape[0])
    for i in range(n_pairs):
        m = compute_lag_metrics(sim_muscle[i], bio_traces[i])
        per_trial.append(m)
    return {
        "per_trial_lagged_corr_mean": float(np.mean([t["lagged_corr_max"] for t in per_trial])),
        "per_trial_lagged_corr_median": float(np.median([t["lagged_corr_max"] for t in per_trial])),
        "per_trial_phase_lag_mean_ms": float(np.mean([t["phase_lag_ms"] for t in per_trial])),
        "per_trial_phase_lag_std_ms": float(np.std([t["phase_lag_ms"] for t in per_trial])),
    }
```

**Full set of wandb-logged lag metrics per muscle (logged every eval cycle during training):**

| Metric | Meaning |
|---|---|
| `eval/emg_{m}_mean_corr` | Pearson r of trial-averaged traces (current metric, kept) |
| `eval/emg_{m}_mae` | MAE of trial-averaged traces (kept) |
| `eval/emg_{m}_trial_corr_mean` | Mean of per-trial Pearson r |
| `eval/emg_{m}_trial_corr_median` | Median of per-trial Pearson r |
| `eval/emg_{m}_trial_mae` | Per-trial MAE (kept) |
| `eval/emg_{m}_lagged_corr_max` | Max corr over ±50 ms lag window (mean traces) — **primary metric** |

| `eval/emg_{m}_phase_lag_ms` | Same in ms |
| `eval/emg_{m}_lagged_corr_at_0` | Corr at lag=0 (= mean_corr, for sanity) |
| `eval/emg_{m}_lagged_corr_at_neg5` | Corr at lag=-12.5 ms |
| `eval/emg_{m}_lagged_corr_at_pos5` | Corr at lag=+12.5 ms |
| `eval/emg_{m}_lagged_corr_fwhm_steps` | Peak width — narrow = precise timing |
| `eval/emg_{m}_per_trial_lagged_corr_mean` | Per-trial lagged corr, averaged |
| `eval/emg_{m}_per_trial_lagged_corr_median` | Same, median |
| `eval/emg_{m}_per_trial_phase_lag_mean_ms` | Avg per-trial best lag — bias |

Mirror all of the above into `scripts/emg_comparison.py` for Stage 2 re-evaluation.

**No training-reward changes.** Everything here is eval-side; `lagged_corr` and friends are computed during the existing eval pass and logged to wandb like any other eval metric. The PPO loss, task reward, and all cost terms (`--control-cost`, `--control-diff-cost`, `--saturation-cost`) are unchanged.

**1.4 Acceptance tests for Stage 1**
- Synthetic test: two identical sine waves → `lagged_corr = 1.0`, `phase_lag_steps = 0`, `trial_corr_mean = 1.0`.
- Shifted-by-5-steps sine pair → `lagged_corr ≈ 1.0`, `phase_lag_steps = ±5`, `mean_corr ≈ 0.3` (decoupled).
- Clipped vs unclipped peak: with `--emg-norm-percentile 98`, `mean_mae` > 0. With `--emg-norm-percentile 100`, `mean_mae` ≈ 0 on trivially-matched traces.

No Stage 1 code is merged until all three acceptance tests pass.

### Stage 3 — Branch-gated retraining

Branch is decided by the Stage 2 matrix. Only one branch runs.

**Branch 1: "Already solved under p100."**
Trigger: ≥1 existing checkpoint clears all four primary gates under `--emg-norm-percentile 100`, with `trial_corr_mean ≥ 0.4` both muscles and `|phase_lag_steps| ≤ 4` both muscles.
Action: 5-seed replication of that cell. ~15 runs at 1 GPU each.

**Branch 2: "Shape is right but timing offset is large (|lag| > 8 steps) and consistent."**
Trigger: any cell has `lagged_corr_max ≥ 0.80` on both muscles but `|phase_lag_steps| > 8` on at least one.
Action: No retraining. The `lagged_corr_max` already captures the shape quality; we **declare success on shape** and report the measured lag as a known, systematic offset — likely a reference-alignment or clip-start offset, not a policy failure. Verify by shifting `clip_start_frame` by the measured lag in the eval script and checking if `lagged_corr_max` moves onto `mean_corr`. No new reward term is added.
Cost: 0 retraining runs; ~30 min analysis.

**Branch 3: "Shape truly caps below 0.80, need physics."**
Trigger: p100 renormalization does not raise `lagged_corr_max` above 0.80 on triceps, and per-trial metrics confirm it isn't a single bad trial dragging the mean down.
Action: 5 seeds × top 2 s13 cells under new infra, PLUS 4-cell shoulder-damping mini-scan (fix `--force-scale 1.1` at anchor A, vary `--shoulder-damping` ∈ {3e-7, 6e-7, 9e-7, 1.2e-6}, 3 seeds each). Total: 10 replication + 12 shoulder scan = **~22 runs**.

**Branch 4: "Per-trial normalization is the real fix."**
Trigger: `--emg-norm-mode per_trial` (one-cell probe run in Stage 2) produces `lagged_corr_max` at least +0.10 higher on both muscles than dataset mode.
Action: Implement `--emg-norm-mode {dataset, per_trial}` in the trainer, retrain top 2 cells × 3 seeds. ~6 runs.

**Branch-4 probe** runs as part of Stage 2: re-evaluate s13-armM-anchorA-fs1p1-s2 with per-trial normalization applied in the eval script (trainer-side implementation deferred to Branch 4 itself).

## Success criteria (s15 as a whole)

**Primary sweep-ranking metric:** `min(biceps_lagged_corr_max, triceps_lagged_corr_max)` — weakest muscle wins. Phase-invariant, so it measures shape directly without letting a lucky lag inflate the score.

s15 ships when any cell achieves, on the median across ≥3 seeds:

- `eval/episode_reward ≥ 400`
- `eval/emg_biceps_lagged_corr_max ≥ 0.80` **(headline — well above s13's mean_corr=0.70)**
- `eval/emg_triceps_lagged_corr_max ≥ 0.80` **(headline — decisive over s13 triceps ceiling ~0.5)**
- `eval/emg_biceps_trial_corr_mean ≥ 0.5` (per-trial shape consistency)
- `eval/emg_triceps_trial_corr_mean ≥ 0.5`
- `|eval/emg_biceps_phase_lag_steps| ≤ 8` (≤ 20 ms at ctrl-dt=2.5 ms; lagged_corr absorbs some phase so gate is relaxed)
- `|eval/emg_triceps_phase_lag_steps| ≤ 8` (≤ 20 ms)
- `eval/emg_biceps_mae ≤ 0.15`
- `eval/emg_triceps_mae ≤ 0.15`

All measured at `--emg-norm-percentile 100`.

**Phase-lag tie-breaker.** If two cells both clear all gates, prefer the one with smaller median `|phase_lag_ms|` across both muscles.

**No reward-term changes in s15.** The PPO loss and task reward remain identical to s13. If Stage 2 shows shape is right but timing is persistently off, the "fix" is post-hoc lag-shift in the metric (already covered by `lagged_corr_max`), not a new reward term. This keeps s15 a single-variable-at-a-time experiment over s13.

## Parameter budget

Stage 1: 0 GPU, ~1 day code + unit tests.
Stage 2: 8 eval-replay runs, ~20 min each = ~3 h GPU.
Stage 3: 0–22 training runs depending on branch.

Per-run cost at 800M steps: ~1.5–2 h on 1 GPU. Stage 3 worst case (Branch 3, 22 runs) on 4 GPUs in parallel = **~11 h wall-clock**, fitting the user-approved 12 h budget. Branches 1, 2, 4 complete in < 6 h.

Total worst case: ~30 training runs. One-quarter the GPU cost of s14, far higher information yield.

## Risks

- **R1.** p100 normalization could over-compress if a single spike slips the bandpass+envelope filter. Mitigation: acceptance test inspects per-muscle histograms of normalized values; alert if tail >0.95 quantile is a single outlier.
- **R2.** Lagged-corr at ±20 steps could create a false "the answer is just a lag of 18" result if the underlying shape correlation is weak. Mitigation: require `lagged_corr ≥ 0.6` AND `mean_corr` not catastrophic before declaring branch 2 victory.
- **R3.** Stage 2 may reveal that no existing checkpoint is close, forcing Stage 3. Planned for.
- **R4.** Seed variance is large (median bcorr std = 0.20). All success criteria are stated on median-of-3-seeds to absorb this.

## Rejected alternatives

- Another per-muscle ratio grid (like s14). Falsified by s14 data: 0 runs at R≥400 ∧ bmae≤0.15.
- Tau_act/tau_deact sweep in isolation. No prior evidence it's the bottleneck; deferred unless Branch 3 shape-cap confirms.
- Reward-shaping without metric audit. Shaping toward a broken metric would bake the clipping bug into policy behavior.
- Going straight to a sweep without Stage 1. Would replay s13/s14 at lower resolution with the same blind spot.

## Out of scope

- Changes to the reference XML or skeleton.
- Changes to the PPO trainer or observation space.
- Video-diagnostic overhaul.
- New muscles or joints.
